# 滚动时域：主动调拨前置（tau-before-q）调整建议

> 分支：`tau-before-q`（从已推送的 `main` 新建）。
> 本文记录用户提出的新时序建议；实现以本分支代码和测试结果为准。
> 原始权威模型 `docs/滚动时域.md` 暂不改；本文件是待验证的调整方案。

## 一、新时序

旧时序（`main` 当前实现）：

\[
s_t \to q_t \to \Theta_t \to (y_t,\tau_t) \to s_{t+1}
\]

新时序：

\[
s_t \to \tau_t \to q_t \to \Theta_t \to y_t \to s_{t+1}
\]

- \(\tau_t\)：第一阶段，无情景索引，基于 \(s_t\) 决定；
- \(q_t\)：第一阶段，无情景索引，基于“\(\tau_t\) 后的库存”决定；
- \(\Theta_t\)：阶段末实现；
- \(y_t\)：追索，有情景索引，从“\(\tau_t\) 后的库存 + 本期到货 \(o_{1,t}\)”中满足需求。

状态转移：

\[
S^{end}_{r,t}=I_{r,t}+\tau_{r,t}-\sum_s y_{s,r,t}+o_{1,r,t},
\qquad
I_{r,t+1}=S^{end}_{r,t}.
\]

数值上 \(I_{t+1}=I_t+\tau_t-\Sigma y+o_1\)，与旧时序
\(I_{t+1}=(I_t-\Sigma y+o_1)+\tau_t\) 相等；状态转移公式不变，
改变的是 \(\tau\) 的决策时点和约束口径。

## 二、TwoStageLP

### 2.1 第一阶段 tau 变量

在 `qfirst` 之后新增：

```python
self.taufp = [lp.var(f"taufp[{r}]", lb=0.0, ub=float(self.Imax[r]))
              for r in range(N_R)]
self.taufm = [lp.var(f"taufm[{r}]", lb=0.0, ub=float(self.Imax[r]))
              for r in range(N_R)]
```

### 2.2 确定性 tau 约束（只加一次）

```python
# I_r + tau_r >= 0
lp.le({self.taufm[r]: 1.0, self.taufp[r]: -1.0},
      float(self.state.I[r]), name=f"tau_lo_f[{r}]")
# I_r + tau_r <= Imax_r
lp.le({self.taufp[r]: 1.0, self.taufm[r]: -1.0},
      float(self.Imax[r] - self.state.I[r]), name=f"tau_hi_f[{r}]")
# tau_r <= sum_{m != r} I_m
rhs_src = float(self.state.I.sum() - self.state.I[r])
lp.le({self.taufp[r]: 1.0, self.taufm[r]: -1.0},
      rhs_src, name=f"tau_src_f[{r}]")
# sum tau = 0
```

### 2.3 期初容量改为 tau 后

\[
(I_{r,t}+\tau_{r,t})+\sum_{l=1}^{L-1}o_{l,r,t}+q_{r,t}\le I^{\max}_r.
\]

代码中等价于：

```python
lp.le({self.qfirst[r]: 1.0,
       self.taufp[r]: 1.0,
       self.taufm[r]: -1.0},
      float(self.Imax[r] - self.state.I[r]
            - self.state.o[:, r].sum()),
      name=f"cap_init[{r}]")
```

若 \(I+\tau\) 无法使期初状态满足容量，LP 不可行；这是合理的。

### 2.4 当前期与未来期的 tau

情景循环内，\(\tau=t\) 的 `taup/taum` 直接引用 `taufp/taufm`；
\(\tau>t\) 仍创建逐情景变量。对所有期统一：

\[
S^{end}=I+\tau-\sum_s y+o_1,\qquad I_{next}=S^{end}.
\]

\(\tau=t\) 的 `tau_lo/tau_hi/tau_src/tau_bal` 已在 2.2 做确定性版本，
情景循环跳过；\(\tau>t\) 的追索 tau 使用相同的“tau 前库存”口径：

\[
I_{r,\tau}+\tau_{r,\tau}\in[0,I^{max}_r],\qquad
\tau_{r,\tau}\le\sum_{m\ne r}I_{m,\tau}.
\]

### 2.5 结果增加 tau_first

`TwoStageResult` 增加 `tau_first`；`solve()` 提取
`taufp - taufm` 并校验 tau 后的 cap_init。

## 三、RecourseLP

- 构造函数增加 `tau_in`；
- 不再创建 `taup/taum`；
- `pas` 使用 \(I+\tau^{in}\)；
- \(S^{end}=I+\tau^{in}-\sum_s y+o_1\)；
- \(I^{out}=S^{end}\)；
- 保留 `cap_end`；
- 目标保留 `-C_sY + h/2 I_out`，不再有 tau 成本项；
- `RecourseResult.tau` 返回 `tau_in` 作为常量。

## 四、仿真主循环

每期：

1. 解两阶段 LP，得 \(q_t^*,\tau_t^*\)；
2. 执行 \(\tau_t^*\)：可用库存变为 \(I_t+\tau_t^*\)；
3. 执行 \(q_t^*\)：进入在途；
4. 观测 \(\Theta_t\)；
5. 解追索 LP，输入 \(q_t^*,\tau_t^*,F^{new}\)，得 \(y_t^*\)；
6. 递推：

\[
I_{r,t+1}=I_{r,t}+\tau_{r,t}^*-\sum_s y_{s,r,t}^*+o_{1,r,t},
\]

\(n_{t+1}\) 和在途递推不变；\(o_{next,L-1}=q_t^*\)。
**不要再额外加一次 \(\tau\)。**

## 五、文档同步

`docs/滚动时域.md` 的第一节时间线和约束 (1)(3) 需同步为：

- 时间线：观测 \(s_t\) → \(\tau_t\)（第一阶段）→ \(q_t\)（第一阶段）→
  \(\Theta_t\) → \(y_t\)（追索）→ 递推；
- 容量：\((I_t+\tau_t)+\Sigma o_t+q_t\le Imax\)；
- tau 约束分为第一阶段确定性版本和 \(\tau>t\) 的追索版本；
- 追索 \(S^{end}=I+\tau-\Sigma y+o_1\)，\(I_{next}=S^{end}\)。

## 六、技术细节

1. \(\tau_t\) 对所有情景共用，必须确定性可行；
2. \(\tau_t\) 的来源是 \(I_t\)，不是 \(S^{end}\)；
3. \(q_t\) 的容量上界会被 \(\tau_t\) 收紧/放松：流入仓位 q 上界减少，
   流出仓位 q 上界增加。

## 七、预期效果

- \(\tau_t\) 可能非零：两阶段 LP 中 tau 通过 \(I_{t+1}\) 有跨期收益，
  执行时不再被追索 LP 覆盖为 0；
- 停机/待修成本下降；
- 采购成本可能略升；
- 与 SDDP 的 gap 有望缩小，但 SDDP 的 cuts 仍包含更丰富的跨期信息，
  差距不会完全消失。

## 八、实现口径补充（与本分支一致）

为保证新时序在所有期一致，本分支对 \(\tau>t\) 的 tau 约束也按
“tau 前库存” \(I_\tau\) 处理，而不是旧版的 \(S^{end}\) 来源。
这是对建议中“追索 tau_src 仍用 S_end”的必要修正：若 \(\tau\) 已在
\(S^{end}\) 中，继续用 \(S^{end}+\tau\) 会把 tau 计算两次。
